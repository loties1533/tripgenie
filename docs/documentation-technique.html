Expression des besoins Contexte et objectifs du projet

🎯 Problème identifié

Planifier un voyage complet (vols, hôtel, activités, budget) prend en moyenne 4 à 6 heures de recherche sur des dizaines de sites. L'utilisateur doit comparer, convertir, calculer et coordonner manuellement.

💡 Solution TripGenie

Un chatbot IA qui collecte les besoins en 3 échanges maximum, suggère des destinations personnalisées, puis génère un pack complet (vols Amadeus, événements PredictHQ, itinéraire IA) en moins de 45 secondes.

Composants métier côté serveur scoring.js et claude.js

Algorithme de scoring multi-critères (scoring.js)

Algorithme scoring.js : chaque critère est normalisé [0,1] puis pondéré selon le mode de voyage

Extrait de code — scoreVol() : Le score d'un vol est calculé en combinant le prix (normalisé entre 50€ et 2000€), la durée (60 à 720 min) et le nombre d'escales, avec des poids différents selon le mode luxury (privilégie le direct) ou student (privilégie le prix). 
// scoring.js — scoreVol() : note un vol selon le mode
function scoreVol(vol, mode) {
  const prixScore  = 1 - normalise(vol.price, 50, 2000);  // moins cher = mieux
  const dureeScore = 1 - normalise(vol.duration_min, 60, 720);
  const directScore = vol.stops === 0 ? 1 : vol.stops === 1 ? 0.6 : 0.3;

  if (mode === 'luxury')  return directScore * 0.5 + prixScore * 0.1 + dureeScore * 0.4;
  if (mode === 'student') return prixScore * 0.85 + directScore * 0.15;
  return prixScore * 0.5 + directScore * 0.3 + dureeScore * 0.2;
}

Jeu d'essai fonctionnel Fonctionnalité la plus représentative : génération de pack

La fonctionnalité centrale de TripGenie est la génération d'un pack voyage complet via POST /api/ai/generate. Le jeu d'essai ci-dessous teste les cas nominaux et les cas limites.

Cas 1 — Pack standard (mode party, données complètes)

destination: "Ibiza"
origin: "Paris"
departure: "2025-07-15"
return_date: "2025-07-22"
travelers: 4
budget: 3000
mode: "party"
Pack JSON avec :
• 2 vols (aller + retour)
• 2 hôtels avec prix/nuit
• 3 activités nightlife
• Budget ventilé en 6 catégories
• Score entre 0.70 et 1.00
• Code HTTP 200
Pack JSON reçu :
• flights: [{CDG→IBZ, 185€}]
• hotels: [Ushuaïa, Montesol]
• score.total: 0.87
• budget_breakdown OK
• HTTP 200
• trip_id: UUID sauvegardé

Cas 2 — Destination inconnue (IATA non résolu)

destination: "Zanzibar"
origin: "Paris"
budget: 2500
mode: "relax"
• Pack généré avec données IA
• Avertissement vols non disponibles
• Vol estimé en fallback
• HTTP 200 (pas d'erreur bloquante)
• Pack généré correctement
• warnings: ["Destination Zanzibar non reconnue, vols réels indisponibles"]
• Vol fallback estimé inclus
• HTTP 200

Cas 3 — Données manquantes (validation entrées)

// destination absente
origin: "Paris"
budget: -500
mode: "party"
• HTTP 400 Bad Request
• Message d'erreur explicite
• Aucune requête IA envoyée
• HTTP 400
• {"error": "destination requise"}
• Pour budget≤0 : {"error": "budget invalide"}
• Pas d'appel IA

Cas 4 — Authentification (token invalide)

GET /api/trips
Authorization: Bearer FAUX_TOKEN
• HTTP 401 Unauthorized
• Message "Token invalide"
• Aucune donnée retournée
• HTTP 401
• {"error": "Token invalide"}
• Pour token expiré : {"error": "Session expirée, reconnecte-toi"}

Cas 5 — Scoring multi-critères (scorepack)

vol: {price:185, duration_min:120, stops:0}
hotel: {stars:4, price_per_night:200, rating:8.5}
events: [{category:"festival"}, ...×8]
mode: "party", travelers: 4
• score.total entre 0.75 et 1.00
• details.events élevé (mode party = 40%)
• details.vol correct (vol direct = bonus)
• Objet {total, details} retourné
• score.total: 0.87
• details.events: 0.85
• details.vol: 0.79
• details.hotel: 0.72
• {total: 0.87, details: {...}}
Écart analysé : Le score obtenu (0.87) est cohérent avec les données : vol direct à 185€ (bon score prix + direct), 8 événements festifs (score events élevé en mode party), hôtel 4★ bien noté. Aucun écart significatif constaté par rapport aux attentes.
